Both the ordinary build instruction and request-specific schema instruction state that the parent tags remain in the file: a text span inside LI/P must not be mistaken for the entire LI/P. Raw markup, inline formatting and valid paragraph/list insertions remain supported.

Its correction now includes bounded numeric shapes for the rejected list and Original-source lists in the same section, with explicit empty-row indices. These are location/context hints, not asserted list matches or current-parent edit anchors. No source prose, code, scripts or styles is added by this feedback. It explains that `expectedNumber` is inferred from the damaged proposal and cannot prescribe the Original's new numbering. Oversized shapes are omitted explicitly, without changing validation or silently dropping checks. The single shared construction correction, Candidate/repair/time budgets, all original checks and final questions remain unchanged.

These checks can establish a clearer input/feedback boundary, not that the model will successfully use it; that needs a new source-bound trial.
