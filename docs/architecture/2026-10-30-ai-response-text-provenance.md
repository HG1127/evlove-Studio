# Physical response text provenance for recoverable review evidence

D2's order journal stores complete parsed scoring responses and their canonical hashes. A parsed-result hash does not identify the provider's original HTTP response text. The additional opt-in request-local observer supplies that separate identity without storing prompts, headers, credentials or raw response content. Contracts owns the Zod envelope; backend composition owns AsyncLocalStorage and SHA-256. No Domain or Harness infrastructure dependency is introduced.

Each observation binds the trusted physical usage call ID, Mission/Job, operation/model/protocol/attempt, request-body text SHA-256, fully received response-body text SHA-256, UTF-8 byte length, HTTP status and receipt time. This hash covers the decoded HTTP body text re-encoded as UTF-8, including its whitespace; it does not claim the compressed network bytes or a canonical parsed-result identity. The parsed order response and its existing hash remain necessary. The observer follows `readJson` responses returned by the transport, including fully received malformed JSON; intermediate retryable transport responses, SDK internals and interrupted bodies do not gain fabricated complete-body evidence.

The observer is inactive unless explicitly scoped. An active scope requires trusted Mission/Job identity and a string request body before provider I/O. SDK generation is rejected before invocation because its raw HTTP body is opaque. A successful wrapper with no complete observations is rejected. Optional observation persistence completes before returning the parsed response; a persistence failure uses `AI_RESPONSE_PROVENANCE_NOT_RECORDED`, outside the existing format-correction allowlist, and grants no new generation budget. Existing physical retry, one format correction, usage records, occupied claims, scoring rules and old trial verdicts remain unchanged. An interruption is still unknown even if a usage record exists.

This is the low-level provenance prerequisite, not a completed D2 recovery integration. The order-journal owner must bind these observations to the validated order result and persist both within the same original claim. No journal, old Mission or production state is rewritten here. Fixed provider substitutes verify exact hashes, privacy, interrupted-body rejection, trusted scope and failure without repeat requests. These tests do not prove model quality, application lifetime, SOP acceptance, business benefit or Lesson transfer.
