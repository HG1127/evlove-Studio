# Verified failure routing and frozen repair validation

An ordinary Hidden assessment may contain both a verified rejection and a criterion with incomplete evidence. The rejection is actionable without converting the incomplete criterion into a product failure or success. Gate F retains its unverified overall state, checks the physical frozen files, and may target only the verified failed criteria. An otherwise undecided assessment still waits for evidence. Missing physical files, changed bindings, duplicate results, and independent final-paper rejection never authorize this repair shortcut.

For Artifact targets, a complete stored rejection on the same contract, physical Original/Candidate binding, measured-review version, execution policy, and answer-sheet fingerprint can resume toward repair after the observation freshness window. Both independent assessments must be complete. This retains the existing negative verdict; it does not reroll a Judge, refresh the observation time, or supply fresh passing/production evidence. Passing observations retain the existing freshness rules.

The Workflow processes a frozen Experiment or bound failed Validation checkpoint before refreshing the preparatory Visible baseline. Holdout and Gate F still perform their own identity checks. HTTP/connector targets are excluded. A changed scoring contract or model route is still blocked before checkpoint routing.

The real eleventh attempt exposed an earlier planner gate: a protection-evidence request prevented the completed negative verdict from reaching this Workflow path. Scheduling now permits the bound frozen rejection to proceed while keeping that unrelated evidence request pending. It cannot bypass input/clarification/approval requests, an explicit pause, campaign limits, Safety failure, changed evidence identity, or independent final rejection. Domain resource/safety/completion limits are checked separately from evidence readiness, without changing the normal stop policy. A frozen resume with no prior timer binds its time window to the Workflow request timestamp; later iterations do not renew it.

Retaining an already measured Candidate rejection does not require all comparison criteria to be verified. The failed Candidate criterion must cite its own mapped verified executions under the current review policy. The incomplete comparison and other unknown verdicts are retained verbatim, with no Judge reroll, promotion or renewed observation timestamp.

A targeted repair receives a new Candidate identity and frozen files, remains without a Visible winner, and returns to the existing Plan-to-Experiment boundary. Experiment verifies and measures those exact files on the complete Visible suite before ordinary Hidden can run again. It records normal build/execution checkpoints for outages and never rebuilds an unavailable frozen repair. The independent final paper stays reserved and unchanged.

With the user's explicit authorization to send this SOP's complete measured body text to the currently configured repair AI service, repair reuses document observations already present in the matching Candidate's ordinary Hidden answer sheet, using the existing projection and budget. Deployment setting `EVOLUTION_AI_FULL_REPAIR_TEXT_MISSIONS` enables this only for explicitly authorized Mission IDs; empty/invalid settings and other Missions contribute no observations. Candidate identity and the full evidence fingerprint must also match; changed contracts and stale Candidate bindings contribute no observations. No extra Source/HTML extraction, raw script/style/control egress, final-paper content, or final-paper feedback is added. Measured text supplies document scope; only the current exact mutation chunks may supply HTML anchors.

For an authorized HTML repair, the bounded mutation context is further restricted to exact body slices. A pure parser projection omits the head, script/style blocks, and opening tags carrying inline styles or executable attributes. Omission markers cannot become edit anchors, and the model must use text edits even when the projected body fits the context budget. The physical parent remains untouched; materialization applies validated edits to its complete SHA-verified bytes, retaining all omitted code/style bytes. This narrows outbound context and does not replace or truncate the delivered file.

This keeps contracts → core → harness → adapters/apps unchanged. Pure routing and injected execution remain in Harness; physical reads remain in adapters/composition roots. It does not claim that the real pilot's content, interaction protection, independent final, delivery, business benefit, or learning-transfer gates have passed.
