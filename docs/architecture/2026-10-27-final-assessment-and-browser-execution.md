# Preserve completed blind assessments and execute declared browser predicates

Status: implemented for validation, 2026-10-27.

Confirmation fourteen passed all six Visible and nine ordinary Hidden cases under the all-user-goal policy, on one exact frozen file. Its independent paper then recorded two below-minimum hard scores alongside incomplete protection and baseline evidence. Readiness called the whole result pending. Resuming artifact acceptance could invoke a new independent assessment of the same Candidate and replace the completed result.

The paper also declared browser predicates on six `artifact-runtime` cases. That mode selected document semantic execution, while the native HTML port correctly declined predicates outside its supported source-grounded profile. The final runs had no browser receipts for those declarations. Model summaries cannot establish those browser assertions. The historical result remains unchanged and unaccepted.

## Decision

A completed independent assessment is retained on resume, including partial or negative results. It cannot be replaced by another final execution or fed into targeted repair. A pending assessment still blocks acceptance; this change does not turn missing evidence into product failure. Core also blocks a claimed positive final result when its browser declarations use a semantic/static/roundtrip/manual mode, so old semantic passes cannot substitute for those predicates on a later acceptance resume.

A hard criterion's negative verdict can settle the round despite unrelated evidence gaps only when the existing Candidate/input/paper bindings match, the non-demo Candidate measurement covers the full distinct reserved suite, the criterion/result identities are unique, and its distinct case references exactly match that criterion's cases. Every such run must be verified, nonempty and error-free. Browser declarations additionally require the run's physical artifact hash to match the scoped frozen Candidate. Unknown, duplicate, mis-scoped, partial and contradictory records cannot strengthen a failure. All existing acceptance requirements remain necessary for a positive result.

The optional `browserAssertionModes` field extends `independent-final-execution-v1` without reinterpreting historical contracts that omit it. The current backend advertises only `external-runner` for declared browser predicates. Its execution-contract fingerprint changes. New paper generation must preserve interactions, assertions and thresholds and select the actual browser route; it must not delete assertions or substitute semantic claims. The existing single preplanning contract correction may correct an unreserved paper. Once Candidate feedback exists the paper cannot be replaced.

Backend final execution also checks this capability binding before any executor call. Both server current/Candidate runners reject declarations on unsupported semantic/static/roundtrip/manual modes as unverified before reading stored evidence or invoking substitute execution. Native receipts remain governed by their existing exact-plan/original/frozen-file checks. The general external route retains its supplied predicates and the Sandbox isolation policy. This adds no host HTML execution, model retry budget, threshold relaxation or new data transfer.

## Evidence and limits

Regression checks cover mixed verified-negative/partial outcomes, missing comparison evidence, duplicate/orphan/wrong-case identities, contradictory status, absent browser receipts, repeated acceptance resume, contract fingerprints and the existing bounded preplanning correction. Both executor sides reject the invalid route and preserve external predicates. A static replay against confirmation fourteen verifies the new preflight rejects its six incompatible declarations and acceptance resumes with zero final rerolls, zero repair requests and no state writes.

Confirmation fourteen's sealed paper, scores and Candidate remain unchanged. Local checks and this static replay are not a new real final pass. Accepted exact-byte delivery, controlled human/business benefit and causal transfer to unseen tasks remain unproved.
