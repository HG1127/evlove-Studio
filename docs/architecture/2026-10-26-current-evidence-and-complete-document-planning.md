# Current evidence and complete document planning

Date: 2026-10-26. Status: implemented; offline verification only. No trial restart, acceptance threshold change or paid-call authorization.

## Evidence and problem

The sealed third SOP confirmation planned edits only to pages 010–013, while `AC-REFINE-DETAIL` requires effective configuration refinement across chapters. Its Problem narrative described those four pages as an acceptance requirement. The actual Visible case and rubric do not impose that scope. The intake interpretation contains detailed suggested page groups and historical provider JSON advice; those remain stored context, but are not new measured defects or replacements for the actual contract.

A local regression on `8fc7ebf` confirmed that Plan lacked the current compact Baseline, criterion IDs/minima and per-criterion assessment gaps. It received the selected diagnosis, historical failure strings and retrieved excerpts. Problem/Diagnosis already filtered deferred Original-only comparisons, but Plan's grounding used raw failure strings again. The planning payload therefore did not clearly separate the present evidence, inferred local scope and the complete user goal.

## Decision

Core now projects versioned `planning-baseline-evidence-v1`: every actionable current criterion keeps its ID, original minimum, verification status, verified score/evidence/gaps and Visible case identities. Ambiguous, partial or demo scores are not presented as verified measurements. Original-only comparison rows are disclosed as deferred, while their full Candidate requirements stay in the rubric. Above-minimum user-goal gaps are improvement opportunities, not extra mandatory per-criterion score increases.

The planning contract keeps all rubric IDs/minima, configured metrics, explicit human clarifications and the original command. A shared instruction states that the selected Problem, a local diagnosis, intake interpretations and historical advice cannot narrow that contract or invent new requirements. A located evidence reference does not prove semantic entailment. Provider formatting failures do not by themselves establish a product defect. No stored narrative or historical verdict is rewritten.

Harness receives complete document context through an injected, Zod-validated port. For an explicitly authorized HTML Mission, application composition reads the actual current parent, verifies it against the frozen Champion or Baseline Original reference and provides the complete declared static-body text projection plus all article headings/identities. The projection excludes actual scripts/styles, executable attributes, templates/noscript/SVG and runtime/visual verdicts. Existing code examples in the readable body remain text. Oversized or failed reads pause before model I/O; a requested complete context never falls back silently to an easier excerpt.

Problem, Diagnosis and Plan use that context. Independent-final reservation receives Original-only context before planning; neither its questions nor later Candidate context enters mutation planning. Revalidation still determines quality independently. Bounded fallback HTML excerpts also exclude programs/styles and retain the article outline, but carry no complete physical-document claim. Multi-Target excerpts share their budget so later targets do not receive empty content; exceeding the source-count capacity stops rather than silently omitting a Target.

The context extraction reduces the existing preparation module's responsibilities. Contracts own the DTO, Core owns assessment/projection policy, Harness owns budgeting/routing and apps own physical reads and exact-Mission body authorization. Dependency direction and the existing 23-node workflow remain unchanged.
