Status: implementation and verification in progress. No new accepted SOP or real evolution is established.

The known, signature-bound tool renderer reads paragraph elements from mini-cards, then removes the source grids. A code-only card therefore loses its instruction in the rendered page. The generic native profile and source code-block retention do not establish that this instruction remained visible.

For a newly proposed Candidate under that exact renderer, Core may project the complete unchanged code-only card text into **one** additional paragraph before freezing. The original PRE/CODE bytes stay intact. One paragraph preserves the generic-step branch; adding two would change the whole page to the renderer's rich-tool branch. The existing search-index compiler then derives the new frozen metadata. Existing frozen files, Original-source records and accepted output are never rewritten.

Only an unambiguous, physical, short, code-only mini-card directly inside a tool-page mini-grid qualifies. Its exact code block must match the Original in the same section. Interactive/typed/nested/markup-bearing inputs and unrelated/table layouts remain untouched. The adapter must establish the known program and style identity first. Original/Original calls remain unmodified, the operation is idempotent, and the ordinary post-compilation retention and paragraph checks still apply. No script, style or code block is changed or executed by this compiler.
