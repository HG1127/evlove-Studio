# Bounded construction correction inside an already claimed repair

Status: accepted, opt-in. No layer-direction exception.

## Measured problem

Real SOP confirmation nine used MiniMax-M2.7-highspeed on pushed `4c5350a`. Its first frozen Candidate retained 57/57 Original code/instruction blocks and passed native checks, but paired user-goal quality regressed. The already claimed sole repair returned a proposal that failed the existing pre-freeze Original retention check at 55/57. No repaired bytes were frozen. The Workflow completed; no ordinary Hidden, independent final, Gate F or delivery occurred.

The initial builder already supports one construction correction for typed pre-write anchor/layout/retention/paragraph errors. Targeted repair stopped immediately on the same error classes. The sealed real failure proves that asymmetry was reached. The raw rejected repair proposal was not retained, so local tests cannot replay its exact missing blocks. The real error, accepted parent bytes and complete parent evaluation remain preserved.

## Decision

Add optional `experimentPolicy.repairConstructionCorrection = repair-construction-correction-v1`. Unselected legacy Missions keep their original behavior and failed attempts remain terminal. Both Visible and ordinary Hidden targeted repairs share the same composition function and existing repair debit.

For a selected policy, permit one additional model proposal only after the shared construction classifier recognizes a typed pre-write failure. Reuse identical issued body anchors, physical parent hashes, failed-criterion scope, feedback and independent-final binding. Reserve one new Candidate ID across both construction proposals. The materializer preflights every Target before its first Blob write. It never restores omitted code, rewrites model prose, changes grades or promotes an unchecked file.

Before correction, recheck existing campaign limits and the live bound control Job. Expired time, exhausted resource limits or cancellation stop the second request. Ordinary storage/network errors, out-of-scope changes, no-ops and actual evaluation failures do not trigger construction correction. A failed correction propagates directly; it cannot become a loop, another repair allowance or a new time window. All successful repaired bytes still require the complete original Visible, ordinary Hidden, independent final and Gate F path.

The existing provider schema-repair mechanism remains separately bounded and every physical request remains recorded by normal usage instrumentation. Estimated campaign cost is not actual billing. No historical trial is restarted and no new real-effect result follows from local tests.

## Verification

Connected local tests use real body-anchor resolution, parent hash checks, code-retention preflight, materialization and frozen-byte readback. Only renderer admission/derived metadata, model responses and the Artifact store are injected. They cover unchanged legacy behavior, one successful correction with zero premature writes, second failure without a third proposal, wall-time/cost/round limits, durable cancellation, out-of-scope output and persistence failure. They preserve the input Mission and its consumed repair counter. These are synthetic regression tests, not a new SOP acceptance or learning-transfer result.

Final local checks passed 209 related tests across 14 files, 11 Runner tests, TypeScript/production build, architecture check and changed-file lint. The new opt-in path still requires a separately registered real confirmation; these results do not change C9.
