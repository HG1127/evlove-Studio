# Independent absolute threshold calibration

The previous directional-only method can qualify a stable semantic false pass. A local counterexample on `9ddf0d6` declares two paragraphs necessary, deletes one in each labelled negative control, and supplies consistent Original 100 versus Candidate 97/96 with a fixed minimum of 95. Original-copy controls, negative deltas, source anchors and synthetic canonical approvals all agree. Both v2 calibration and the old full-admission helper return ready even though the known negative subjects are rated above the original acceptance minimum. This is a synthetic method counterexample, not a real provider measurement or a production admission.

`judge-calibration-plan-v3` adds mandatory independently labelled `originalPass` and `candidatePass` values for every control criterion. Each numeric minimum remains unchanged. An expected pass requires both the model's pass flag and a score at or above that minimum; an expected failure requires a false flag and a score below it. The Original is checked as well as the Candidate, in both orders. Each criterion must include labelled observations on both threshold sides. Relative decrease above the threshold may be a legitimate labelled regression, but cannot replace a separate known failing threshold example. A zero numeric minimum cannot support this two-sided numeric calibration and remains unsupported by v3 rather than being silently increased.

The exact-zero pairwise policy from v2 remains available: independently labelled non-improvement requires zero and false for both the self-reference and the negative Candidate; the positive control must clear its original threshold and Safety requirement. Unknown labels are rejected by the schema. Direction labels must agree with the absolute oracle. Neither direction nor a score/pass disagreement can waive an absolute expectation.

New full confirmation uses `confirmation-admission-request-v2`, explicitly requiring v3 calibration. V1/v2 plans remain parseable, and their historical directional method decisions remain reproducible. The current full-admission helper rejects legacy requests and legacy plans; readable directional history cannot authorize a new full confirmation. The helper returns `full-confirmation-admission-v2` and still grants no trial authority, model budget or acceptance.

Canonical approval validation applies to both v2 and v3 plans. The complete preregistered plan digest includes all absolute oracle labels. Changing a label invalidates the previously bound independent approval. Labels stay outside the model-under-test payload; they are not model-provided fields or target scores. Unverified source review cannot be converted to a boolean oracle automatically. Existing source/model/rubric/paper, two-order, copy, timing, source-text anchor and application-load requirements remain in force.

Shared fixtures live in Testkit with explicitly synthetic scores, labels and approval ports. Tests demonstrate the stable false pass being blocked, Original misclassification, inconsistent score/flag pairs, missing threshold-side coverage, unknown or contradictory labels, obsolete admission protocols and retained zero-reference behavior. No old trial is rescored or reopened, no threshold is relaxed, and these checks do not establish current real model calibration, SOP improvement, business benefit or causal experience transfer.
