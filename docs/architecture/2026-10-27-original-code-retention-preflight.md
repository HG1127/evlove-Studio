# Reuse native code retention before freezing known SOP proposals

Status: accepted, 2026-10-27.

## Observation

Confirmation six constructed a real file but native protection rejected it: 53 of 57 Original PRE/CODE blocks met `original-text-with-numbered-instruction-append-v1`. Static comparison locates two modified PRE/CODE pairs on slides 43 and 55. Each retains its Original text as a prefix and adds explanations inside the block. The existing policy does not permit these extensions. Both viewport style comparisons passed; this cannot override code retention or Safety FAIL. The trial ended without Hidden, independent-final execution, delivery or lessons.

## Decision

Keep the existing retention algorithm, its numbered-prose compatibility and native evidence contract unchanged. Add a typed pure Core assertion around the same predicate. The backend invokes it **after** supported lossless layout/search compilation, before any Target is frozen. Only the already-recognized SOP renderer takes this compilation path; unknown HTML and other file formats retain existing behavior.

After supported prose separation restores an Original block's exact bytes, the assertion passes. Otherwise a typed construction error exposes only the existing policy and counts. The initial builder can use its existing single pre-write construction correction to return a complete proposal with additional explanations in ordinary paragraphs outside Original code blocks. Anchor, semantic-layout and code-retention errors share that same one correction. No nested correction, new Candidate, experiment repair, timer extension or new allowance is introduced. A correction that still fails stops before writing. Errors after storage, actual Visible/Hidden/final failures and forged error-shaped objects cannot gain a construction retry.

This does not relax any protection, modify an accepted file, resume a terminal trial or replace native validation. Every future frozen file still needs the complete Visible suite, ordinary Hidden, the pre-reserved independent paper, Gate F and exact-byte delivery.

## Verification and limits

The regression fails before the fix. Injected runtime tests demonstrate rejection before writes, one same-context correction, successful exact-byte freezing after prose is placed outside the block, exhaustion, sharing with an earlier anchor correction and no new restriction for unknown renderers. Tests also verify the existing numbered-instruction extension policy and that retention is evaluated after lossless compilation.

Static replay through the actual backend composition recognizes the real frozen SOP and rejects its unchanged 53/57 result before freezing. Original, frozen Candidate and sealed Mission hashes remain unchanged, with zero AI/Sandbox calls or remote writes. The replay proves the earlier check, not a repaired model proposal, a passing real confirmation, user benefit or causal lesson transfer.
