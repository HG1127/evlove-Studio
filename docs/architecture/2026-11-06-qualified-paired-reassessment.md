# Qualified evaluator replacement after a known schema failure

The legacy physical paired-judgment claim deliberately survives failures and unknown results. In C42 it correctly prevented another Job from scoring the same files and paper. It also prevented the explicitly authorized replacement of the failed evaluator with an independently calibrated evaluator: both old HTTP results were complete, but their output failed the task schema and produced no admissible pair.

Retain the legacy physical key and its default behavior. An optional, server-only registrar pin may admit a new assessment namespace for an exact physical scope and a different, qualified evaluator. The pin binds the old claim and immutable schema-failure event, old and target physical routes, target aggregate scoring route, runtime commit, qualification/audit hashes, real authorization digest, and expiry. A registrar must verify the pinned qualification and authorization provenance out of band; an evaluated model or client Mission cannot self-certify them.

Runtime rechecks the old failed Job, failure event, and every paired HTTP start/result between claim and failure. Missing, partial, unknown, unfinished, mismatched or non-stop results are rejected, as are any legacy stored paired orders. The claim and order journal use one namespace derived only from physical scope and target aggregate scoring route. New Jobs, names, dates, authorization IDs, and repeated calibration documents cannot produce another target budget. Existing history is immutable; old and new orders are never mixed. Same-attempt zero-or-two recovery and conservative judging remain unchanged.

This is an explicit exception to the permanently occupied legacy assessment, not a score retry. The registrar must retain prior failures, carry forward consumed request/repair budgets, keep the original papers and gates, and attest that evaluator semantics are the qualified replacement. A pin creates no time, request, repair, purchase, or deployment authorization. Default production configuration has no pin and keeps the legacy lock.
