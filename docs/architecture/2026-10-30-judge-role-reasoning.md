This does not promise deterministic scores or better acceptance. The existing service, model, protocol and included subscription remain unchanged.

The server-only optional `EVOLUTION_AI_JUDGE_REASONING_EFFORT` now independently selects reasoning effort for `evaluate`, `evaluate-paired`, `evaluate-population`, `artifact-acceptance`, `release-review` and `visual-judge`. Generation, planning, diagnosis and construction retain `EVOLUTION_AI_REASONING_EFFORT` or the provider's existing default. Both fields use the existing Zod enum and are captured together when an environment, explicit or saved Vault connection is pinned. Selection is pure and does not reread mutable environment state between paired orders. Absent an override, wire fields and scoring identities keep their prior behavior. Provider-specific supported values must be respected; this option is not silently translated or simulated. Gateway routes reject this direct-only operator option before provider I/O, as they already do for the general effort setting.

The scoring route hashes the evaluator's effective setting, so a new evaluator effort cannot reuse old scoring evidence. Physical request telemetry hashes the same effective setting actually sent on the wire. Generation settings alone do not change the evaluator identity when an explicit judge override remains the same. The durable physical-attempt claim key is unchanged: a configuration or source update does not authorize rejudging an old Candidate. Existing JSON parsing, schema rejection, one format correction per order, two actual orders, zero-change control, native facts, Safety and all acceptance thresholds remain unchanged. No setting is enabled in this release, saved Vault record is rewritten, provider is added, or public settings DTO is changed.
