# Local native HTML verification

Status: accepted for explicitly selected local Missions. Production remains Vercel Workflow/Sandbox.

The native HTML observer previously required a cloud VM even for local development. A cloud free-tier limit must not force a paid upgrade or prevent a separately authorized local diagnostic. `tools/local-runner` is already the designated local runner migration target in `PROJECT_RULES.md`.

The new `experimentPolicy.nativeHtmlRuntime: local-browser-v1` selects a local execution adapter. It requires an exact Mission ID in `EVOLUTION_HTML_NATIVE_LOCAL_MISSIONS`, a local Node 22+ process and an installed sandbox-capable Chromium browser. Cloud transport permission does not enable local execution. Neither runtime falls back automatically to the other. Unavailable local capability remains UNVERIFIED and stops dependent execution and scoring. Unsupported artifact runners also remain unavailable in this mode.

The composition root loads the public `@evolution/local-runner` package only for local mode. Harness receives ordinary ports and contracts and has no Playwright, Supabase or Vercel dependency. Zod validates physical requests, known renderer identities and returned observations. Original and frozen Candidate bytes, source-derived predicates, navigation/style state, body fingerprints and kernel identity remain bound to the evidence. The legacy VM kernel and V1 serialization remain unchanged.

Only the existing known self-contained renderer is admitted. Both subjects must retain its script, inline executable attributes and style identities. User HTML is data in Node and executes only inside fresh, ephemeral, headless Chromium processes with `chromiumSandbox: true`. Each subject gets a new process and context; service workers and downloads are disabled. A synthetic same-origin document is fulfilled in memory. All other document requests, sockets, frames, forms and workers are denied; popups and dialogs are closed. Browser environment variables exclude service credentials. The headless clipboard is verified with trusted fixtures across both processes before using this route for real work. Browser cleanup failure cannot produce an observed result.

The assertion body is copied statically from the VM observer and checked for parity, including native clipboard fidelity, all controls, navigation, search, paragraphs and the same 50 computed-style properties at 1440 and 390 pixels. Local browser sandboxing is not a cloud VM or production attestation. Version `html-native-observation-v2-local-browser` records that distinction explicitly; evaluators see the boundary. The kernel digest covers the loaded observer, browser setup, launcher and pinned package manifest. Baseline, Experiment and Holdout cache identities distinguish the selected runtime and kernel. Existing V1 records retain their original meaning.

This route changes the execution location, not the eight criteria, Visible/Hidden suites, Safety/Gate F, frozen independent final, repair/time budgets, tested/delivered artifact identity, or the requirements for real business benefit and transferable Lessons. A failed or closed experiment cannot be reopened through this option. Native-only diagnostics and any new confirmation trials must keep separate prospective records and their actual authorization scope.
