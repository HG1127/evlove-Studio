# Mission-authorized native HTML execution

Owner: Evolution OS maintainers. Date: 2026-10-26. This completes a concrete adapter and application composition within the existing Vercel/Supabase stack.

## Authorization and scope

The user explicitly authorized complete SOP HTML, including its existing scripts and styles, to enter an ephemeral Vercel Sandbox with external network denied. This is separate from the earlier body-only AI and private evidence-store consent. The user also authorized one new bounded confirmation trial, preserving the failed pilot: one round, one AI Candidate and at most one targeted repair. No further trial or budget increase is inferred if it fails.

`EVOLUTION_HTML_NATIVE_MISSIONS` records the exact Mission opt-in and defaults off. The adapter supports only the existing known self-contained SOP renderer signature. Unknown renderers retain the ordinary evidence route; this adds no PDF, media or general arbitrary HTML editor.

## Execution boundary

Contracts retain the versioned observation and rendered-text schemas. Core identifies eligible evidence scope and validates complete observations. Harness remains independent of cloud SDKs. The adapter hashes exact UTF-8 inputs, recognizes the known script/style surface, and writes only the two physical HTML files, generic observation inputs and trusted browser kernel to the guest. It does not send the natural-language final paper, independent expected answers, repair prompts or credentials to the native kernel.

The existing trusted Playwright 1.63 runtime snapshot supplies dependencies. Each subject pair runs in a new nonpersistent, network-denied VM with two vCPUs, a three-minute limit, no exposed ports and no guest credentials. A separate browser is started for each subject. `stop()` is awaited in `finally`, before an observed result is returned. Scripts are executed only inside the remote VM.

Apps bind Original metadata to the Mission, source ID, size and physical SHA-256, recheck locked references and frozen Candidate identity, then produce one observation per physical pair and bind each eligible test separately. Baseline, Visible, ordinary Hidden and independent final execution use these ports. Protected structural cases may use the stronger parsed/browser observations; unrelated static tests remain on their existing route. Explicit browser steps are never replaced by the fixed native profile. Actual failures remain failures and semantic quality still requires independent assessment.
