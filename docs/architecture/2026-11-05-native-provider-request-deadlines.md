# Native provider request deadlines

Status: prospective opt-in backend transport repair; production settings unchanged.

The local Node 24.14.1 runtime has an independent 300,000 ms default for response headers and body inactivity. A longer AbortSignal does not extend those defaults. The preceding paired timeout configuration therefore needs a native transport composition, beyond its synthetic fetch tests.

The backend-only public subpath `@evolution/adapters/native-ai-deadline` provides request options that delegate to the existing dispatcher with explicit header/body timeouts. It exposes only the `dispatch` shape it implements, not an invented full Dispatcher lifecycle. It does not create pools or close/destroy/replace the parent. An explicitly supplied custom dispatcher takes priority. Body, headers, handler, receiver and all other dispatch options remain intact. The existing overall AbortSignal, control Job cancellation and enclosing execution deadline still apply; header/body settings are not a total-lifetime extension.

Only an explicit `evaluate-paired` timeout above 300,000 ms enables this path. Direct Chat/Responses resolve it before starting a physical provider usage attempt. The SDK resolves it before `generateText` or SDK usage starts, then supplies `createGateway({fetch})`; that fetch still calls the original global fetch so existing usage/provenance and physical request guards remain effective. SDK retries stay disabled in this explicit mode. Legacy routes and other operations keep their previous model object, fetch options and request payload.

Undici is pinned to the already-installed 7.29.1 with a committed lockfile. The adapter is absent from the browser barrel. Its dynamic import must not initialize a new default Agent before Node has configured its proxy dispatcher. A read-only `Symbol.for('undici.globalDispatcher.1')` probe establishes that an existing compatible dispatcher is present; the public `getGlobalDispatcher()` must then return the same object. This version-sensitive compatibility assertion is isolated to the adapter and checked by a fresh native-runtime test. No passive non-initializing public getter is available in the installed library. If the host has not initialized a native dispatcher and provides no explicit one, or if its identity changes during loading, the request stops with a capability error before provider I/O; there is no silent fallback to a shorter deadline. The real application normally initializes native fetch through its preceding project/Vault reads. Standalone compositions must initialize their own normal native transport or supply a dispatcher.

Dependency loading and dispatcher capability getter failures preserve their cause but are normalized to the same capability boundary; they cannot become a Candidate or output-format failure. Explicit malformed dispatcher values, including falsy values, are rejected instead of silently choosing the default connection.

This changes transport resources, not scoring semantics. Scoring instructions, thresholds, payloads, output contracts, acceptance gates and historical verdicts remain unchanged. Source/config/runtime evidence must bind the new implementation before any complete application qualification. Loopback/no-socket evidence cannot substitute for real model results, SOP acceptance, business benefit or causal transfer.

Verification must cover actual native header and body delays, earlier overall cancellation, explicit/custom and preinitialized proxy dispatcher preservation, missing capability before usage/provider I/O, direct protocols and SDK wiring, legacy wire/route stability, and exclusion from browser bundles. Relevant installed API: `ai 7.0.107` re-exports `createGateway`; `@ai-sdk/gateway 4.0.87` accepts a custom fetch; Undici's public dispatch options support `headersTimeout` and `bodyTimeout`.
