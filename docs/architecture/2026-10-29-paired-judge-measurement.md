# Two-order paired judgment

Status: implemented behind an explicit new-Mission policy; 643 related tests across 40 files, a final 21-test parent-boundary check, all 11 Runner tests, architecture/changed-file lint and the full TypeScript/production build pass. A subsequent case-binding clarification passes 64 focused tests across four files. The first real-provider diagnostic stopped on an invalid case mapping; a new bounded diagnostic is pending. No new real evolution is established.

The C32 Original-only diagnostic sent two identical model requests. Workflow closure varied from 90 to 94 and detail from 80 to 88, exceeding the one-point promotion threshold. Existing Baseline and Candidate judgments also use different framing. Those observations do not prove C32 was judged incorrectly, but separate arbitrary scores cannot be treated as a reproducible effect measurement.

New Missions may explicitly pin `paired-two-order-v1` before planning and independent-final reservation. Legacy Missions retain their existing protocol. Each comparison uses two requests on the same route and the same recorded executions, with version order exchanged. Both versions share one unchanged rubric and paper within each request. The model sees neutral slots; embedded evidence can still disclose roles, so this is order counterbalancing, not a claim of complete blinding.

When both sides have complete hash-bound native rendered bodies for every Target, both document projections use those rendered observations. This avoids supplying the whole Original twice as both a static and rendered document while supplying the Candidate only once. Every per-case compact output and trace is still retained, including non-native cases; case-specific evidence is not relabelled or discarded. If either side lacks complete rendered coverage, the existing observation projection remains in use and its omissions stay explicit.

For each criterion the runtime retains the less favorable **observed pair**: the sample with the smaller Candidate-minus-Baseline difference. Both scores come from that same sample. Neither averaging nor choosing a favorable run is allowed. Both complete raw score summaries, their parsed-result hashes, physical file bindings and input/rubric/paper fingerprints are retained in a versioned receipt. Generic dimensions use the same paired selection. Safety is the worse result for each arm. Ambiguous case aggregates are omitted rather than invented.

Each request also includes an exact duplicate of its Original observations in a third neutral slot. A score, pass or Safety disagreement between these identical observations invalidates the affected measurement; the duplicate is not another vote or extra evidence of quality. Both control summaries are retained. This is a null-control qualification inside the same two requests, in addition to the separate Original/Original diagnostic.

Conflicting minimum-pass decisions or conflicting regression directions make that criterion unverified, rather than a fabricated product failure or success. An unchanged complete Artifact set cannot establish mutation improvement. The existing absolute minima, all user goals, relative gain, Safety, Hidden, independent final and tested/delivered-byte gates remain binding. A comparison missing the new receipt cannot silently fall back to legacy scoring or reuse its old cache. Physical observations are not re-executed by this method.

Contracts own schemas, Core owns conservative selection and qualification, Harness owns comparison assembly and settlement, and the backend supplies model I/O. The new protocol uses the existing provider route, JSON/Zod validation and one normal format correction per request. It does not grant an additional Candidate or repair. A fresh preregistration must account for the two paired requests and any existing format correction within its original time and subscription bounds.

Two judgments are not a statistical confidence interval or proof of human benefit. Independent business outcomes, actual cost and causal transfer remain separate requirements. Real verification must include an Original/Original null control and a changed-file comparison without revising sealed failures or replacing final questions.

V1 binds the uploaded Original-source baseline. A new comparison with an existing Search Champion parent is rejected before spending model calls, including a reselected identical Champion, because its subject hash must not be confused with the preserved Original hash. Completed assessments can still be verified/reused for delivery and learning. This limitation remains incomplete work for later parent-version comparisons; it does not change legacy multi-round behavior. Ranking opted-in challengers uses their own matched gain, rather than unrelated absolute scales from different paired contexts.

Production reserves a durable, canonically read-back Event claim before the first model request, under the trusted Mission/Job scope. Its key binds file hashes, paper and rubric, excluding Candidate names, Job IDs and observation timestamps. Renaming an identical file is not a new budget. Concurrent callers cannot both own it. Failed or unknown invocations retain the claim; an observation timeout is not permission to reroll. Complete stored comparisons are reused or preserved, including inconclusive results. A process failure before its complete Mission checkpoint remains an explicit recovery gap, not an automatic new model budget. Private diagnostics may inject a bounded local claim instead of writing production state.
