# Stop exhausted control output before another Workflow generation

Status: implemented for validation, 2026-10-28.

Confirmation fifteen reserved an eight-criterion independent paper under the new browser execution contract before planning. Both the initial planning request and the gateway's existing single output correction returned invalid final JSON. The error reached Workflow as an ordinary exception. The SDK retried that control Step, which subsequently executed another Original evaluation and problem analysis and moved the checkpoint back to Baseline. No Candidate was constructed. The original trial was cancelled at its original deadline and its result remains unaccepted.

## Decision

The backend control-AI composition classifies exhausted, structured gateway error codes: `AI_OUTPUT_SCHEMA_MISMATCH`, `AI_OUTPUT_INVALID_JSON`, `AI_OUTPUT_INCOMPLETE` and `AI_OUTPUT_MISSING_FINAL`. A Zod schema checks this internal error boundary. After `runServerAi` returns one of those errors, its original output correction has already ended. The control adapter raises the installed Workflow 4 SDK's `FatalError`, retaining only the safe code/operation and a fixed message. It adds no provider request and no raw provider text. The rule covers every task invoked through this control boundary, so a malformed diagnosis, rubric or paper response cannot repeat earlier paid control actions either.

The SDK must not retry that failed Step as another model generation. The existing Workflow catch/finalizer closes the Job and pauses the Mission while preserving its current stage, Baseline, Candidate, final reservation and checkpoint. It does not convert malformed model output into an AI configuration outage or a product verdict. Existing cancellation/generation guards still prevent a late finalizer from reopening a terminal Job.

Unknown runtime exceptions keep their existing handling. Provider availability errors retain the existing capability-wait route. Existing artifact executors use their direct gateway ports and keep their bounded construction/repair paths. The gateway itself retains its original single correction; the change is at the outer control-Step boundary. No time, Candidate, repair, provider-correction or paper-generation budget is increased; no parser or acceptance requirement is relaxed. The SDK stays on the repository's existing 4.8.9 version.

## Evidence and limits

Boundary tests cover each exhausted code, safe error messages, one control invocation, availability separation and unchanged nonplanning recovery. Step/finalizer tests preserve the fatal marker, original evidence and cancellation fences. Gateway tests continue to cover its one existing correction.

These checks establish error routing, not valid output from the real provider. Confirmation fifteen's raw planning responses were not retained; the actual malformed bytes and their precise cause cannot be replayed. The sealed failed trial, its repeated evaluation/analysis, all eight physical usage receipts, original deadline and 15.7-second cancellation-acknowledgement delay remain recorded. There were no physical AI requests after that deadline. A later real bounded trial is still needed; no accepted delivery, controlled business benefit or causal transfer has been established.
