# V2.3 Artifact Runtime

## Problem

V2.2 could understand many file types but still evolved too many of them through a text-centric execution path. That created weak results for presentations, codebases and spreadsheets.

## Runtime profiles

### Presentation
- extraction: PPTX OOXML slides and text runs;
- candidate shape: slide/run blueprint;
- hard gate: slide-level structure and completeness;
- delivery: apply accepted text-run blueprint back to original PPTX package.

### Codebase
- extraction: ZIP manifest + selected editable source file map;
- candidate shape: file map;
- hard gate: file/project integrity;
- delivery: merge accepted changed files into original ZIP.

### Spreadsheet
- extraction: sheets + rows/CSV representation;
- candidate shape: sheets/rows;
- hard gate: preserve required sheet names and workbook structure;
- delivery: rebuild XLSX.

### Workflow
- candidate shape must remain structured;
- generic Markdown section patching is disabled for workflow artifacts;
- integrity requires no structurally invalid/dangling workflow representation.

### Prompt / Document
- deterministic local patch compiler remains the preferred fast path;
- AI full artifact generation is fallback.

## Original binary retention

Original binary files are kept in IndexedDB through `artifact-blob-store.ts`. This allows final materializers to preserve non-text structure instead of trying to reconstruct a PPTX/ZIP from flattened text.

Production should replace IndexedDB with object storage plus immutable source revision IDs.
