# V2.3 Workflow & Performance Redesign

## Six user stages

```text
Define → Baseline → Diagnose → Evolve → Verify → Deliver
```

The internal 9-state runtime is retained, but is no longer the main user mental model.

Every primary stage should answer:

```text
INPUT
what comes in

ACTION
what AI / runner does

OUTPUT
what is produced

DONE CRITERIA
what allows the next stage
```

## Problem vs Root Cause

### Problem
Observable failure only:
- symptom;
- impact;
- frequency/severity;
- evidence.

### Root Cause
Causal hypothesis:
- affected component;
- trace comparison;
- evidence/counter-evidence;
- confidence;
- falsifier.

This prevents the problem page from simultaneously trying to explain the symptom and claim the cause.

## Validation

Old validation mixed Hidden tests, generic metrics, project rubric, release checks, gap analysis, AI advice, retry controls and full technical detail in one long page.

V2.3 reduces it to:

1. Hidden Behavior
2. Artifact Ready
3. Release Ready

### Fast failure path
- select a critical Hidden subset covering Hard Rubric criteria;
- candidate + baseline run in bounded concurrency;
- hard/safety/key regression failure returns immediately;
- no Artifact Acceptance after a failed behavioral gate.

### Acceptance path
- deterministic integrity;
- hard criteria first;
- fail fast;
- soft criteria second;
- detailed evidence is collapsible.

## Latency removals

V2.3 removes/reduces:
- automatic gap-advice call on every validation;
- release-review AI call when a local hard gate already failed;
- full Artifact Acceptance after behavior failure;
- generic AI full-build for structured binary artifacts when a type-specific builder is required;
- repeated full-source context where relevant retrieval is sufficient.

## Runtime observability

Every long operation can report:
- phase;
- detail;
- percent;
- done/total;
- elapsed;
- ETA;
- provider;
- model.

This state is persisted in prototype runtime storage so the user knows whether the job is uploading, generating, executing, evaluating, repairing or waiting on a model.
