# V2.7 · Repository Intelligence & Evidence Runtime

## 为什么 V2.6 的“19% 内容覆盖”仍然不够好

真实 Evolve Studio ZIP 可能包含 170+ 文件。V2.6 已建立完整 Manifest，但为了控制浏览器内存和 AI prompt，只有部分高优先级文件进入 `structuredContent.content`，于是 `parsedEntries / totalEntries` 会出现 19% 之类数字。

这会让用户误以为：

> “系统 81% 的工程都没有读到。”

实际上系统可能已经知道全部文件路径和部分 AST，只是没有把全部源码一次性拼到模型 Prompt。

V2.7 因此废弃“prompt 字符占比 = 解析覆盖”的表达。

## Evidence 层级

Repository Intelligence 只解决：

> “我是否真正读到了和这个目标相关的实现？”

它不解决：

> “真实用户操作是否已经通过？”

因此：

```text
Static Repository Evidence → implementation proof
HTTP/Playwright Runner     → behavior proof
Screenshot / VLM           → visual proof
Roundtrip                  → format proof
```

四类证据继续分开。
