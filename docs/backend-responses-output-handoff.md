# Backend Responses output handoff

Date: 2026-10-09. Base development SHA: `6f79dd33281c706aa529ec3723f45c3f224ce8c8` (the separate short-model-ID repair).

## Observed main-flow blockers

The backend's custom Responses decoder returned only the first text part, truncating valid multipart JSON. It also trusted an aggregate output field without validating the full external envelope and could accept HTTP 200 bodies containing both an error and task-valid JSON. The new pre-fix test suite recorded 8 failures and 1 pass, including a runtime health probe incorrectly reporting ready from such an error body. The existing non-completed-status rejection already worked and remains intact.

The official [text generation guide](https://developers.openai.com/api/docs/guides/text) documents that output can contain multiple items and that SDK aggregate text covers all text output. This repair reads all text parts when an aggregate is absent; it does not introduce streaming or a new provider API.

## Repair and evidence identity

`readCompatibleResponsesOutput` is a public adapter helper sharing the existing Zod envelope contract with browser Responses calls. It validates the external envelope, rejects provider errors and known nonterminal statuses, and joins all text output. The backend retains its completed-only status policy and validates the final decoded JSON against the existing operation schema. Browser compatibility and its existing JSON-format negotiation remain covered. The backend request body, protocol, user-selected JSON format, redirect restriction, timeout, image input and credential redaction are retained; explicit Responses calls do not silently switch protocols or formats.

Responses-capable server scoring routes now bind `responses-output-v1` in their fingerprint. This prevents old scores generated by the prior decoder from being silently reused under the repaired policy. Explicit Chat and Gateway identities keep their existing shape, and an API key rotation does not change public scoring identity. Existing Responses comparisons may require fresh scoring evidence. Frozen Artifact construction and execution receipts are not rewritten by this code change.
